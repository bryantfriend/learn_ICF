Build a seat booking page

Make a page where a learner can book a study seat. Start with a label and button. Then connect the page to the same ICF runner you use in the Academy.

Open the working project

Pick your starting point

  • JavaScript Basic starts with your first line of JavaScript.
  • Beginner checkpoint asks you to check a library request. If you can finish it, try Intermediate.
  • Intermediate checkpoint asks you to wait for a lookup and handle errors. If you can finish it, try Advanced or go straight to Build Every Stage.

Set up your copy

Download the Academy files while you have internet access. After that, all the files for this project are on your computer. Follow the offline setup guide and start the local server with node serve.cjs. Leave that terminal open. In a second terminal or a file manager, copy the seat-project folder to a new folder called my-seat-project beside it. Open http://127.0.0.1:4173/my-seat-project/.

Keep the two folders side by side so the project can find Template/. Open the copy in your text editor. The four files to read are index.html, style.css, page.mjs, and booking.mjs. The sample seat list is in seats.json.

1. Give the form a label and button

Look for the form in index.html. The for on the label matches the id on the input. The name is how JavaScript looks up what the learner typed.

<label for="seat">Seat ID</label>
<input id="seat" name="seatId">
<button type="submit">Book a seat</button>

Change the label to “Which seat?”. Reload and click the label. The cursor should move to the field. Then press Tab to reach the next control. Practice the form in Studio.

2. Make it fit a phone

Read style.css. The fields fill the space in the form. Padding stays inside their width. The outline shows where you are when you use the keyboard.

input { width: 100%; box-sizing: border-box; }
button:focus-visible { outline: 3px solid #1749a9; }

Make the window narrow. Check that the form fits without sideways scrolling. Change the outline color, then press Tab until you reach the button. Keep a color you can see. Practice the CSS in Studio.

3. Turn the form into data

In page.mjs, find the submit handler. A handler is a function that responds when something happens. This handler keeps the browser on the same page and uses FormData to read the field names.

event.preventDefault();
const fields = new FormData(form);
console.log(fields.get('seatId'));

Add the log after the line that makes fields. Open the browser’s developer tools and choose Console. Enter “ a1 ” with spaces and submit. The log should show the original text. ICF cleans the seat ID later. Practice reading the form.

4. Show a helpful message

Find the element with role="status". It can announce changes to a screen reader. textContent puts the message there as plain text. Try changing the success message, then try a blank seat ID. Check what people see in both cases.

When something breaks, say what you expected first. Read the error in Console. Use the file name and line number to find the code. Change one thing, reload, and try the same input again. Practice showing the answer.

5. Connect the page to ICF

Follow the import of createBooking from page.mjs into booking.mjs. The page calls the function with the seats it loaded. Each submit then builds a fresh Intent. The six-stage list shows the helper that runs each step.

  1. Book “ a1 ” as Ava. The page should say “Booked A1.” Open “See which steps ran” and check that all six stages passed.
  2. Try A1 again. The request should stop in Authorize because the seat is taken.
  3. Try B2 as Guest. Permission should fail. Then try B2 as Bo. It should still be free.
  4. Try seat Z9. The lookup should fail in AddContext. Try a blank ID. It should fail in Validate.

The seat list and sample member selector are for practice. Bookings reset on reload. For a real app, get the member ID from a signed-in account and save seats in a store that can handle two requests at once. Try the Studio project or build the full feature from scratch.

See how the page loads JSON over HTTP

Open the Network tab in your browser tools and reload. Find seats.json and check its status and response. A 200 status means the file loaded. The response text is JSON. The page reads it with response.json().

In your copy, change the fetch path to a file that does not exist. Reload. The Network tab should show 404 and the page should show an error. Restore the path, add "C3" to the seats list, and check that you can book the new seat. Practice handling an HTTP response.

Save a checkpoint with Git

Install Git while you have internet access if you want to use it offline later. Open a terminal inside your my-seat-project folder. Use these commands there. git init sets up Git in the project folder if it does not have a repository yet.

git init
git status
git add index.html style.css page.mjs booking.mjs seats.json
git diff --cached
git commit -m "Build seat booking page"
git log -1 --oneline

A commit is a saved version of your files. If Git asks for your name or email, use git config user.name "Your name" and git config user.email "you@example.com" inside this folder, then retry the commit. Use git diff to see what changed after your next edit. Everything here can run on your computer without sending your files anywhere. Practice the commands in Studio.

Build a small change on your own

Add a second seat label or a new room to the project. Before coding, list one request that should pass and two that should fail. Run those requests, read the steps, and record what you saw. Try the last-seat challenge when you want to test retries and two people booking at once.
